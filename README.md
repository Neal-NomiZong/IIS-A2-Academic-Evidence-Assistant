**Project:** University of Birmingham, Intelligent Interactive Systems A2.

## Purpose and boundary

Explore whether a real paper abstract supplies preliminary evidence relevant to a specific research claim. Distinguish topical relevance from actual evidential support, and communicate uncertainty. The system does **not** establish that a scientific claim is true, verify full-text findings, or calculate calibrated confidence.

## Implemented, simulated, and unfinished

- **Implemented (browser):** Original three-case demo; case switching; prewritten explanations; local user actions/feedback/exclusion; live academic search; live-LLM result display; Evidence Trace panel with clear matched/unmatched quotation statuses.
- **Implemented (local Python backend):** OpenAlex search, abstract reconstruction, fresh OpenAlex retrieval by validated work ID when analysing, optional OpenAI Chat Completions call, JSON response validation, and exact case-sensitive substring matching of 0–3 model-suggested quotations against that backend-retrieved abstract. Browser-submitted abstracts are **not** trusted or analysed.
- **Simulated:** All judgments in the original three-case demonstration. The live model's reasoning is generated by a real LLM, but is provisional rather than externally validated.
- **Planned/unimplemented:** scientific correctness checking, automated full-text evidence verification, robust hosted deployment, persistent user feedback, calibrated numerical confidence, systematic performance evaluation. The current `storyboards/` contains two live-mode scenario illustrations and one separate Demo-mode feedback scenario; the original V0.4 diagrams/storyboards are retained under archive paths.

**Key distinction:** `MATCHED IN ABSTRACT` means *identical text was located in the OpenAlex abstract fetched by the backend*. It does **not** mean the inference is correct, that the abstract is complete/accurate relative to the publisher, or that the full paper supports the claim. `NOT FOUND IN ABSTRACT` highlights model-suggested text that did not match exactly (including changes in punctuation or case); these are **not** verbatim citations.

## Windows PowerShell: run locally

1. Extract this ZIP into a **new V0.7 directory**, not over the existing locally edited V0.6. Keep the original directory for a real before/after comparison.
2. In VS Code choose **File → Open Folder**, selecting the new `Academic_Evidence_Assistant_V0.7` directory, then **Terminal → New Terminal**.
3. Run `python -m unittest discover -s backend -p test_server.py -v`. Offline tests do not connect to OpenAlex or OpenAI and do not use a real key.
4. In a terminal in the project root, confirm `Test-Path Env:OPENAI_API_KEY` yields `True` and check `$env:OPENAI_API_KEY.StartsWith("sk-")`. **Never print or share the key.** A new PowerShell window may need the key to be set again; the value does not automatically persist across windows.
5. Set `$env:OPENAI_MODEL = "gpt-4.1-mini"`, then run `python backend/server.py`.
6. Visit **http://127.0.0.1:8765/** (NOT a `file://` URL). Choose a real OpenAlex paper with an abstract. Enter a claim and click **Analyse selected abstract with AI** once. A generation request may incur API costs.
7. Inspect the six assessment fields and the new **Evidence trace — literal abstract match** panel. Expand the original OpenAlex abstract, follow the source link, and manually evaluate the meaning.

If port 8765 is in use, close the old server with `Ctrl+C`. Never run the two versions on the same port simultaneously.

## Safety / data handling

- Backend listens on `127.0.0.1`; API key stays in a server-side environment variable. Never paste a real key into source, frontend, Git, screenshots, or messages.
- Search terms go to OpenAlex; claim + real OpenAlex abstract go to the model provider when analysis is clicked.
- Quotes and abstract are returned to the local browser for inspection. No persistent database is implemented.
- The OpenAlex content and LLM responses are **untrusted**. Model-suggested evidence is mechanically checked for literal presence, but scientific interpretation remains for the user to verify.
- This is a local educational prototype, not production-secure. Do not deploy it publicly without further authentication, rate limiting, and security review.
